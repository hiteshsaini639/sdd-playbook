# Data conventions

Choices every table makes the same way, so nobody chooses them per table.

- **Keys:** UUID v7, generated by the application. It is time-ordered, so it
  indexes like a sequence, doesn't leak counts in URLs, and lets a migration
  create parents and children in one pass.
- **Every table:** `id`, `created_at`, `updated_at`, `created_by`, `updated_by`,
  `deleted_at`. The server stamps who and when, never the client.
- **Deletion is soft** for anything a person might want back. Records that are
  junk rather than gone (spam, a voided bill) get a status instead.
- **Time:** `timestamptz`, stored UTC, **rendered in the viewer's time zone**.
  Exports carry an explicit zone. A business date that is not the UTC calendar
  date (a shop's trading day) is its own column with its rule written down.
- **Money:** integer minor units or exact decimal, never float. Name the
  currency once (per tenant, if multi-tenant).
- **Naming:** `snake_case`, tables plural, join tables both nouns, booleans read
  as assertions (`is_active`).
- **Fixed-choice values are codes** (`localization.md`).
- **Multi-tenant:** `tenant_id` on every business table, applied by the data
  layer from the session (`permissions.md` → Scoping). Add it before the
  second tenant, not after. A backfill across every table plus a review of
  every query costs far more than one column now.
- **Migrated rows** carry `legacy_id`, indexed. That makes the migration
  re-runnable (upsert on it) and traceable a year later.
- **Migrations** are hand-written, reviewed files, applied in order and never
  edited once applied. No schema-diffing at boot.
- **Destructive tooling refuses any database not marked disposable.** Test
  suites refuse to run unless the database name says "test". No override flag:
  a flag is what someone passes at 2 a.m.
